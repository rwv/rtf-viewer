## Maintenance foundation

The repository uses Release Please for release preparation, environment-scoped GitHub credentials for the release bot, and npm OIDC for publication. A pinned upstream source import replaces the initial image-helper copy; Dependabot proposes submodule and dependency updates for review. Build and browser/package checks run before merging those updates. The [release procedure](releasing.md) and [reuse evaluation](reuse-evaluation.md) describe the boundaries.

The issue #5 maintenance slice expands compatibility codepages, filters irrelevant font completions while preserving explicit relayout, and corrects integral raster sizes at 150 PPI. The production browser gate now runs in Chromium, Firefox and WebKit. This closes specific M1/M2 compatibility gaps without extending the table, list or complex-script fidelity claims. See [verification](verification.md) for the source/package distinction and measured results.

The issue #21 slice replaces the table text fallback with real row and cell geometry, and the issue #20 slice adds a validated producer corpus manifest so that fidelity work is chosen from measurements. Both are recorded in [compatibility](compatibility.md) and [corpus](corpus.md); neither extends the list, merge, nesting or complex-script claims.

## M3 boundaries that must be explicit

Vertically merged cells, nested tables, repeated header rows and keep-together rows are distinct features from ordinary tables and are not implied by them. Horizontal merges are implemented: a `\clmrg` continuation folds into the cell that starts the range. Split rows and rows taller than a page are implemented: a row that does not fit continues at a line boundary and each fragment is drawn as a closed box, borrowing the opposite border for the edge the break itself created. Lists model numbering semantics: the cached list text is used only where no definition resolves. Inline PNG/JPEG does not imply WMF/EMF or arbitrary DrawingML shapes. WMF/EMF evaluation must include rtf.js's separate renderers and licenses, including production import behavior and unsupported record visibility. That evaluation has now been run against a real producer metafile; see [reuse evaluation](reuse-evaluation.md). Reading the bitmap out of a metafile does not imply playing its vector records: a metafile that draws with lines and curves still shows a placeholder.

Editing, source-format saving and round-trip fidelity are outside the read-only project. Embedded objects are not executed.

## Next concrete work

1. Replace the clamped timer that layout and paint yield through. `pnpm bench:render` now measures both, and the measurement retired the Worker question for layout latency: an 87-page document lays out in 402 ms and a page paints in 10 ms, both in interruptible slices, so a serialization boundary and a Worker font problem would buy nothing. What is left is the yield primitive itself, `setTimeout(0)`, which a browser clamps to about four milliseconds once timers nest; that is issue #41, and it is separate because the mid-paint relayout test currently holds a yield by replacing `window.setTimeout`. Issue #19's parser fuzzing and parse-latency baseline are delivered; its Word and TextEdit producer artifacts remain blocked on producer access.
2. Vertically merged cells and nested tables, both of which need cell spans that a row-independent layout cannot express today. Horizontal merges, alignment and shading are done.
3. Close the `lo-2427-line-height` corpus delta, the last open difference on the table sample apart from the page break it moves. The engine's line box is 0.65 pt shorter per row than the producer's for 10 pt Liberation Serif, which is a measurement question, not a table question, and it moves page breaks in long documents.
4. Grow the producer corpus, prioritizing permission-cleared Word and TextEdit files and list/image cases. Every new document needs provenance and classified deltas in `fixtures/corpus.json`; see [corpus](corpus.md).
5. Play the vector records of a metafile that has them. Issue #35 delivered the DIB decoder that this corpus's metafile actually needed, so a rasterising producer's drawing now appears; a metafile drawn with lines and curves still shows its placeholder. The next slice needs a producer document that emits such a metafile, because an unmeasured renderer is not evidence.
6. Picture bullets and numbering that depends on stylesheet inheritance, both of which need the stylesheet cascade first.
7. Expand the installed-package gate to additional bundlers and platforms; retain the Chromium/Firefox/WebKit production checks as the browser baseline.

Rendering lifecycle maintenance: Canvas and bitmap completion checks reject superseded layout revisions, with deterministic browser regression coverage.

Engineering maintenance now includes enforced format/lint and merge gates, separate browser/Worker/Node type environments, and a shared archive/registry consumer. Broader producer fixtures, fuzzing and performance baselines remain follow-up compatibility work; they are not implied by passing release checks.
